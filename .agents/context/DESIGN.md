# StylistTG Design Context

## Direction

Product dashboard. Design serves operational clarity.

## Rules

- Use `@stylisttg/ui` primitives when an equivalent exists.
- Avoid nested cards, oversized hero metrics, decorative gradients, and duplicate status panels.
- Prefer compact tables, status pills, inline warnings, short helper text, and progressive disclosure.
- Keep information density high enough for operators, but do not make the interface visually heavy.
- Safety and runtime state must be visually explicit: disabled, gated, dry-run, shadow, live, blocked, warning.

## Copy

- User-facing dashboard copy should be Russian.
- Technical diagnostics may expose concise English identifiers when they help debugging.
- Avoid vague reassurance. State the actual runtime state and next action.
