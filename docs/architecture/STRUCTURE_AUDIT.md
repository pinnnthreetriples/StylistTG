## 2. Current Architecture Snapshot

The repository is now a compatibility-first modular monolith:

- Backend feature ownership lives under `backend/app/modules`.
- Runtime role metadata lives under `backend/app/runtime`.
- Feature-specific queue ownership is module-level, while `app.job_queue` remains generic infrastructure plus compatibility imports.
- Frontend modularization has started under `apps/dashboard/src/modules`.
- Legacy import paths remain intentionally compatible for API, services, and worker call-sites.
- Security baseline checks are represented in GitHub workflows and documentation.

Public behavior remains outside this audit scope and must stay unchanged:

- API paths: `/api/account-update`, `/api/warmup`, `/api/me`.
- Workflow ids: `account_update`, `warmup_due_sessions`, `warmup_dispatch_tick`.
- Queue names and deterministic warmup job ids.
- Job models, auth/workspace semantics, frontend UX, database migrations, and TDLib/live gates.
